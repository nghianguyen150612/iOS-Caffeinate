# iOS-Caffeinate v0.1.0-rc1 — Draft Release Notes

**Status:** Draft only. No tag or GitHub Release has been created.

## Purpose

iOS-Caffeinate is a native C11 CLI and foreground daemon for bounded awake requests on rootful jailbroken iOS. It provides local diagnostics, IPC-controlled assertion lifecycle, timed holds, and scheduled awake windows while the daemon is running.

## Intended platform

- iPad mini 2 A1489 / Apple A7 ARM64.
- iOS 12.5.7 with Amethyst/Procursus rootful bootstrap.
- Thin `arm64` iOS binaries targeting iOS 12.0.
- Debian rootful package architecture `iphoneos-arm`, package `com.ioscaffeinate.cli`, version `0.1.0~rc1-1`.

The P010 signing profile is opt-in and scoped to the tested bootstrap; it must not be generalized to other jailbreaks without new evidence.

## Capabilities and test observations

The CLI provides status, diagnostics, bounded start/stop, and schedule management. Scheduled awake evaluation requires the daemon to be running. It does not wake a suspended device. Holds and schedule windows are bounded; there is no indefinite mode.

Operator-reported testing on October 18, 2026 records successful IOKit assertion acquisition and release, timed expiry, explicit STOP, and SIGTERM cleanup when binaries were signed with the explicit private no-container entitlement. The same report records 24/24 authenticated locked-screen LAN SSH commands and 24/24 authenticated Tailscale SSH commands during the observed period. The P009 evidence review is still required, and the no-assertion comparison has not been completed. These observations do not show that the assertion caused continued network availability.

## Limitations and safety

- Signed `.deb` installation, upgrade/removal, and rollback have not been tested on device.
- Battery and thermal impact, longer idle reproducibility, unattended 24/7 reliability, and scheduled wake are unverified or not validated.
- Successful IOKit calls do not guarantee that iOS will avoid deep sleep.
- A signature or entitlement match does not prove jailbreak trust or device package acceptance.
- CI artifacts remain unsigned and are not installation-ready release packages.
- The launchd template is inactive. No installer starts the daemon or changes SSH/Tailscale.

## Installation and rollback

There is no authorized installation command in this draft. A later supervised install requires a signed, inspected `iphoneos-arm` package, exact SHA-256 verification, profile/signer review, collision and maintainer-script preflight, SSH/Tailscale baseline, direct physical recovery, and a backup/rollback plan. Follow [P010 device acceptance](../P010-DEVICE-ACCEPTANCE.md) and [P010 package validation](../P010-PACKAGING-VALIDATION.md). Do not install an unsigned CI package or run an unattended test.

## Candidate artifact record

The exact-source CI manifest is generated by the P010 Actions job. It records the unsigned CI package separately from any signed local candidate. A signed package hash, signature-integrity result, device execution result, and package acceptance result must not be filled in until those artifacts and observations exist.
