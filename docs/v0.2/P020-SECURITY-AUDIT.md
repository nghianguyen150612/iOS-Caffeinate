# P020 Privileged Runtime and Package Security Audit

## Scope and method

Static source review covered `src/daemon.c`, `src/power.c`, `src/recovery.c`, `src/service.c`, `src/schedule.c`, `src/server_mode.c`, `src/server_policy.c`, `src/health*.c`, P018 evidence/export and package-preflight scripts, rootful package builder/validator, `DEBIAN/preinst`, `DEBIAN/prerm`, manager operations, signing metadata, CI artifacts, and all existing release workflows. P020 adds negative tests for release evidence and unsigned provenance. No target filesystem or hardware was accessed.

## Findings summary

No confirmed Critical or High exploitable source defect was identified in this cloud review. This is a code-review result, not a conclusion based on CI success. The reviewer receipt contract now requires detached GPG signatures under a separately managed trust keyring; candidate-bound signer evidence admission, physical evidence, and independent reviewer receipts remain release blockers documented in [P020-FINDINGS.md](P020-FINDINGS.md).

## Required operational controls

The P020 evaluator refuses arbitrary hardware `PASS` fields. It validates hash-bound evidence references and requires a detached GPG signature on each independent review receipt, checked against an absolute reviewer keyring provided outside the evidence bundle. The trust manager must provision that keyring through a separate reviewer identity process; absence of the keyring or a valid signature leaves evidence `UNVERIFIED`. This proves which trusted key signed a receipt, not that the underlying event occurred. A human reviewer must inspect P009 raw evidence and the P018 sanitized derivative separately. P019 simulated fixtures are explicitly rejected for hardware gates.

A successful iOS cross-build, Mach-O inspection, package check, or exact-head workflow does not establish signature acceptance, device execution, assertion release on the target, launchd behavior, sensor availability, SSH continuity, or endurance.
