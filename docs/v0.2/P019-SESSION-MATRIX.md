# P019 Session Matrix

Phases run in order. A phase does not inherit authorization from an earlier phase. An operator separately authorizes each state-changing action.

| Phase | Entry gate | Planned work | Required evidence | Gate outcome |
|---|---|---|---|---|
| 0 — Read-only inspection | Operator present, independent recovery available, initial inspection authorized. | Identify device; inspect package, process, socket, launchd, P014 journal, P015 policy, schedules, telemetry, logs, evidence. Run a command only if that exact binary is installed. | Device identity, package/binary identity, process/socket/service state, assertion ownership, recovery journal, policy/schedule state, resource availability, existing evidence. Unknown is not PASS. | Any mismatch or unknown critical cleanup state blocks Phase 1. |
| 1 — Package acceptance | Exact P010 signer and package provenance; P011 preflight; separate install/upgrade/removal/rollback authorization. | Follow P011 stable v0.1.0 acceptance. Record installed path verification. Later prepare a separately identified signed development candidate. | Release and signer manifest, package hash, install output, package state, CLI/daemon hashes and runtime, rollback artifact, P009 events. | Do not proceed to power trials until stable acceptance and candidate identity are resolved. |
| 2 — Foreground daemon lifecycle | P011 PASS, correct candidate, safe P014 state, separate attended session authorization. | Start foreground daemon normally, verify existing IPC and read-only status, manually stop cleanly, observe process exit and socket cleanup separately. | Launch/exit, IPC status, socket state, journal state, assertion ownership before/after, operator attendance and recovery readiness. | No SIGKILL, launchd mutation, journal reset, or automatic repair. |
| 3 — Controlled idle and SSH | P012 prerequisites and exact protocol v1 trial/order. | Manually run 24 A/B/C/D trials. Each trial uses one route, one quiet interval, at most one probe. Preserve LAN and Tailscale results separately. | P012 trial record, screen lock, quiet start/end and contamination count, daemon/assertion state, acquisition/release, host result, timebases, uncertainty, resources, carryover. | Stop on any safety condition. SSH failures are outcomes; host-key failure stops immediately. |
| 4 — Repeated bounded reliability | Phases 0–3 passed safety review; no unresolved cleanup. | Three separate-date attended periods, four manual 180-second cycles each, five-minute unasserted rest between cycles. | Each cycle’s acquisition, release, duration, daemon exit, restart status, cleanup/journal, charging/resource state, attendance, rest, timebases, incidents. | 12/12 clean cycles required for this registered scope. No renewals or automatic loop. |
| 5 — Lifecycle and recovery review | Earlier phases complete and evidence preserved. | Review supported P013/P014 behavior; observe clean manual shutdown and current recovery state. | P009 lifecycle events, P014 journal/provenance, explicit unsupported features and limits. | Do not test launchd mutation, automatic restart, reboot persistence, crash injection, or reset recovery state. |

Phase 0 suggestions when installed: `ic --version`, `ic doctor`, `ic package status`, `ic package verify`, `ic service status`, `ic service recovery status`, `ic server policy explain`, `ic schedule doctor`, `ic health status`, and `ic evidence inventory`. Missing command or unknown output remains unknown. Do not use a v0.1.0 binary to claim P018/P019 command behavior.
