# P018 CLI Contract

The binaries remain `ios-caffeinate` and `ios-caffeinated`; `/usr/local/bin/ic` remains a relative symlink to the CLI.

## Discovery and version

```sh
ic --help
ic help
ic help schedule
ic help service
ic help server
ic help package
ic help evidence
ic --version
```

`ic version` is an alias for `ic --version`. Version output is stable `key=value` text. `package.version` comes from package source metadata, `source.commit` from the build checkout, `build.kind` identifies a development/dirty build, and `release.channel` is `DEVELOPMENT`, `PRE_RELEASE`, `STABLE`, or `UNKNOWN`. Direct builds without trustworthy build macros report `UNAVAILABLE`/`UNKNOWN`. P018 does not create a v0.2.0 release identity.

The current known schema versions are reported individually as `schema.pNNN`. These are format identifiers, not evidence that any record or hardware gate is present.

## Command map

| Command | Behavior |
| --- | --- |
| `ic status`, `ic doctor`, `ic wake status` | Read-only diagnostics. Doctor never starts the daemon or acquires an assertion. |
| `ic schedule list|next|validate|doctor|conflicts|explain` | Read-only schedule inspection and previews. P017 execution is unauthorized; scheduled wake is unverified. |
| `ic schedule add|enable|disable|remove` | Configuration-changing operations through the existing daemon protocol. New definitions are capped at 300 seconds. |
| `ic server status|doctor|plan|policy ...` | Read-only policy and runtime diagnostics. Eligibility is not execution authorization. |
| `ic server trial start --for <duration>` | Explicit bounded assertion operation, maximum 300 seconds. |
| `ic service status|doctor|plan|recovery status|recovery plan` | Read-only lifecycle and recovery diagnostics. |
| `ic service enable|disable|start|stop|restart`, `recovery reset ...` | Existing state-changing operations; P013/P014 gates remain fail-closed and device semantics remain unverified. |
| `ic health status|battery|thermal|doctor|sources` | On-demand read-only observations. Battery/thermal may be unavailable. |
| `ic package status|verify|doctor|uninstall-check` | Existing read-only manager checks. |
| `ic package upgrade-check <absolute-deb> [--rollback-artifact <absolute-deb>]` | Read-only upgrade planning. No package scripts or install command runs. |
| `ic package rollback-check <absolute-deb>` | Read-only artifact and rollback readiness report. Exit code compatibility is described in [P018 package preflight](P018-PACKAGE-PREFLIGHT.md). |
| `ic evidence status|inventory|validate` | Read-only evidence discovery/validation. |
| `ic evidence export --dry-run` | Read-only export preview. |
| `ic evidence export --output <absolute-new-directory>` | Explicit privacy-filtered file creation. Not an acceptance operation. |
| `ic probe`, `ic start`, `ic stop` | Existing bounded power/assertion operations. Manual `start` holds may last up to 24 hours. |

`probe` can acquire and release an assertion briefly. It is not a read-only diagnostic. Status, doctor, schedule previews, package checks, and evidence inventory do not acquire assertions.

## Structured output

JSON is opt-in:

```sh
ic doctor --json
ic package status --json
ic package verify --json
ic evidence inventory --json
ic evidence validate --json
```

JSON uses `schema_version: 1`, deterministic key ordering where generated by Python, `null` for unavailable package metadata, explicit status strings, and no conversion of `UNVERIFIED` to `false`. Existing subsystem `key=value` output remains available.

## Shell use

Quote paths in POSIX `sh` and interactive zsh:

```sh
ic package upgrade-check "/var/root/candidate package.deb"
ic package rollback-check "/var/root/previous package.deb"
ic evidence export --output "/var/root/ioscaffeinate-p018-export"
```

The output directory must not already exist. P018 help and documentation examples are syntax-checked with `/bin/sh -n` and `zsh -n`; examples do not assume GNU-only flags.
